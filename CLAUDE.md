1. **No implementation unless the owner explicitly says so.** "Explicitly" means a direct instruction in chat to implement a named job or phase ("implement job X", "start Phase 1"). Approving a plan, answering a question or agreeing with a summary is **not** permission to implement. When permission is given, it covers only the job or phase named.
   - **Always consult the owner before implementing.** Before any code is written, the orchestrator presents the job spec (goal, files to touch, approach, tests) and waits for a clear yes.
   - **Never improvise on anything ambiguous.** If the specs are unclear, contradict each other, are silent on a point, or leave more than one reasonable way to do something, **stop and ask** — this applies to the orchestrator and every subagent (subagents report the ambiguity back to the orchestrator, which asks the owner). Present the choices as a short numbered list, each with its trade-off, plus a recommendation if there is one, and wait for the owner to pick. Do not pick a "sensible default" and carry on.
   - The first task, when told to start, is Phase 0 (section 9).
2. **Claude is the orchestrator (Opus).** It writes plans and job specs and delegates all coding to three **Sonnet** subagents (crawler, backend, frontend and overlay). A separate **Opus general-purpose** subagent reviews every job before hand-off. See section 10.
3. **Git is read-only for Claude and every agent.** Allowed: `git status`, `git diff`, `git log`, `git show`, `git blame` and other read-only commands. Never: commit, branch, checkout of a new branch, merge, rebase, cherry-pick, stash, tag, push, pull, reset, or `git worktree add`. The owner does every git write.
4. **No live calls to GGG while coding.** Agents work from recorded responses and test fixtures. Live requests only happen in short, low-volume smoke tests the orchestrator runs through the shared rate limiter.
5. **No secrets in code or in agent context.** Discord webhook, account-hashing salt and (later) the GGG client secret live only in the server's `.env`.
6. **poe.re code is AGPL-3.0: never copy it.** Its generated data may be used under its data terms (section 4.4). Awakened PoE Trade's code is MIT: its item parser may be reused with the licence notice kept.
7. **Only free tools and services.** Anything that requires payment is out of scope.
8. **Crawler safety rules are non-negotiable** (section 5.3): 80% hard cap, hard-coded daily maximum, one shared limiter, circuit breaker on any 429.
